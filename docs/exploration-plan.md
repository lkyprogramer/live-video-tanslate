# 本地日译中字幕探索与验证执行方案

2026-11-07。后续探索以本文为执行入口，首轮记录见 [optimization-plan.md](optimization-plan.md)，已完成实验见 [optimization-results.md](optimization-results.md)。新增反馈 [gemini-next.md](gemini-next.md)、[new2.md](new2.md) 作为研究输入。本文结合当前源码、原始记录和 Astra max 独立审查编写。

目标是在本机 M1 Pro、32 GiB 上，经 Chrome 标签页音频生成实时、可读、语义正确的简体中文字幕。入口沿用 16 kHz 单声道 PCM 与 v1 服务。阶段完成靠可检查的证据决定，默认配置的替换由最终验收决定。

## 1. AI 执行入口

收到“按本方案执行”后，从 E0 或最新未完成的阶段继续。依次执行 E1、E2、E3、E4、E5，通过门槛的候选进入 E6，再进入 E7。E0 的人工复听可以等待，其他已有输入的任务继续。E2 的源码诊断可以与 E1 的准备并行，模型推理和资源采样串行。

1. 核对工作区状态、现行合同和最近证据。用新的持久目录 `p0/evidence/exploration-<时间>/` 保存本轮结果，模型和隔离环境放 `.model-cache/`。历史目录作为只读输入。
2. 创建 `run-settings.json`，保存代码状态、输入 SHA-256、模型 revision/文件哈希、完整实参、提示词、种子、运行时与量化。Git 有未提交内容时另记受影响源码哈希。当前配置从 [profiles.toml](../engine/config/profiles.toml) 读取。
3. 创建 `progress.json`。每个阶段记录 `pending/running/passed/failed/provisional/needs_human/unavailable/skipped`、产物路径、结论与下一入口。`needs_human` 精确落在待复听项；独立任务继续执行。`skipped` 写明未满足的进入条件。必需素材缺失时记录缺口，先按现有准备入口恢复同源同哈希材料，其他已具备输入的任务继续。
4. 每个实验先写假设、唯一变量、控制组、预算和停止条件，再运行。失败保存原始错误；依赖故障最多做两次有变化的排障。超过本节预算就结束该候选并转到下一项。
5. 一次最多加载一个候选组合。执行中清理本次进程，阶段结束检查 diff、非预期文件和后台模型。总结分别列事实、待确认和下一入口。

本轮预设预算为 E1–E4 各最多 2 小时。新 ASR 两个正式席位，部署不可用时全轮最多一次替补，实际尝试至多三个checkpoint；新 MT 最多一个，E6 最多两个组合。E5每个候选最多3小时。每个模型只选一种精度和一个运行时做首筛。资源不足或没有可用日语实现时记 `unavailable`，继续已有输入的阶段。预算扩大由用户决定。

本地下载公开权重、隔离安装依赖、实验探针和非破坏性测试属于执行范围。音频和转写留在本机。提交、推送、发布和远程付费调用按用户授权执行。

### 所有阶段共用的评分

- 冻结相同的 34 个语义单元与必要信息。分别保存 `historical`、`source_provisional`、`human_verified` 的参考状态。只报告实际有证据的等级。待确认项保留在原分母，另列采用两种判定时的结果。
- 每条判断保存参考版本、候选匿名标签、对应输出 ID、原文片段、必要信息、缺失内容、关键误译类型和证据等级。类型覆盖数字、否定、人物关系、动作关系、专名和新增无关内容。同一候选在原本未命中的单元里新增关键错误也计数。
- 日文可读的固定输入足以核对 MT 是否改变其数字或否定。实际音频年份、切片听写和句末需要复听。AI 文本复核写 `ai_reviewed`，人工复听写 `human_verified`。多模型一致仅作定位线索。
- 主指标为句末后 2／3／5 秒正确中文覆盖，另报 15 秒漏错，分母包含所有参考项。多条输出合成一项时，以最后一条必要输出到达计时。正确核心信息齐备后才允许提前匹配。
- 首条分别记录任意、语义正确、稳定正确中文，四短句从真实语音起点计时。缺失写 `null`；统计短句 P90 时按无穷大计失败。
- P50/P95 附命中数。共同命中延迟与全分母覆盖一起报告。命中不足 20 项时将 P95 标为小样本描述，进入全量才检验尾延迟门槛。
- 当前 `chinese()` 字符过滤纳入实际可用输出。简体、完整语义和无额外解释由译文复核判断，字符过滤通过不等于语义通过。

## E1. 先验证 VAD 推进粒度和尾帧

**输入**　同一份连续 PCM 与现有 Silero 文件，参数和上下游模型均取现行基线。

1. 先用真实 200 ms 包复现 88 个切片。确认 sherpa 2.0.1 的来源和当前模型窗口。该版会合并一次调用内的窗口状态，边界可能受调用粒度影响。
2. 实验层加持续 FIFO，网络仍是 200 ms，服务端按模型要求的完整窗口推进。当前基线模型窗口为 512 samples。保存余数，窗口处理时间取 PCM 已实际到达的时间。比较“整包调用”和“完整窗口逐次调用”，其他变量一致。
3. 先保持原生 EOF 行为，单独记录 `received/processed/residual/padded` 样本数。若证实原生 Flush 遗漏真实尾样本，再单做 EOF 修正组；填充仅辅助模型计算，输出时钟与字幕范围夹在真实样本内。
4. 直接调用离线VAD适配器，以3200／512 samples和不规则切块核对相同PCM的顺序与分窗结果；覆盖511／512／513 samples的尾部。v1 WS始终使用3200 samples完整包，仅最后一包可短。确认会话重建清空状态，EOF重复调用保持同一结果。
5. 生成切片起止、放行时刻、字节哈希及两组 ASR/MT 对照。优先检查 `csj-task/1` 是否真正恢复打开动作。只有时标变化时停止该优化。

**完成**　`vad-granularity.json` 和尾帧检查能逐样本解释差异。有效内容恢复且保护项未退步时，用原9段连续PCM重新生成两组切片，分别经同一M0的两种子评价全部34项。达到通用离线门槛才进入E6候选池，单纯更多片段不晋级。证据来源见 [sherpa 固定实现](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/voice-activity-detector.cc)。

## E2. 解释 WhisperKit 的空结果

**输入**　原 43 段、19 个空结果、原先正确片段和静音负例，沿用 [Swift 探针](../p0/whisperkit/Sources/WhisperKitProbe/Probe.swift) 的固定版本。

1. 在锁定源码/实验构建记录输入长度、是否进入主解码循环、decoder 调用次数、原始 token、清理前后文本及返回状态。原构建与诊断构建先做同配置输出一致性检查。
2. `windowClipTime` 默认 1 秒，主循环有严格长度条件。原 19 空结果中 4 段≤1秒，其余 15 段为 1.014–9.714 秒。先复现该分组，再仅把窗口裁剪改为 0 做一组对照，记录极短输入处理及 EOF。
3. 当前固定版本 `TextDecoder` 的 `noSpeechProb` 为常量 0，默认 0.6 阈值不会触发 no-speech 跳过。其余长片空结果继续沿 token/时间戳解析、提前结束与后处理定位，逐条说明或标 `unexplained`。
4. 一次修正只针对已复现的分支，最多一个配置修正与一个有直接证据的适配修正。对原 43 段、静音和保护项重跑，恢复真实信息后再接同一 M0。

**完成**　`empty-result-audit.json` 覆盖全部 19 个空结果，每项含分支证据或未解释原因。只恢复语气词、产生更多幻觉或语义无净收益时结束该候选。43段诊断有实质语义恢复后，再扩到原88切片、34项和M0两种子评分，通过通用离线门槛才进入E6候选池。实现修复与模型质量结论分别记录。[固定解码源码](https://github.com/argmaxinc/argmax-oss-swift/blob/1bbc57cb7fe6410248a685b1c5a3c6d56adc2ed4/Sources/WhisperKit/Core/TextDecoder.swift) · [窗口循环](https://github.com/argmaxinc/argmax-oss-swift/blob/1bbc57cb7fe6410248a685b1c5a3c6d56adc2ed4/Sources/WhisperKit/Core/TranscribeTask.swift)

## E3. 再验证 VAD 模型

**输入**　E1 已核对的窗口/尾帧策略与连续 PCM。控制和候选取相同策略。

1. 校验本机 `silero_vad.onnx` 的 SHA-256 为 `9e2449…bb1fd6`，与官方资产全值对比。它来自 k2-fsa 重导出的 Silero v4。保留原件。
2. 首筛三组为现行 v4、官方 v6.2、FireRed **Stream-VAD**。阈值/等待/模型 lookahead 各自完整记录，先保持 600 ms 业务静音等待。若换适配器，先让旧 v4 经新适配器复现控制结果，记录剩余实现差异。
3. 每个模型最多一组官方默认加一组有证据驱动的阈值变体。v6.2 的输入/状态签名先验烟测。FireRed 核对 16 kHz 幅度约定、25 ms 特征窗、10 ms 步长和持续模型状态。用常驻特征流或官方重叠规则保持跨包窗口连续，比较整段与分块的特征帧数及数值，量化不可避免的 lookahead。
4. VAD 的漏语音、音乐误收和起止精度只在有对应标注的范围计量。没有人工标注时报告样本覆盖和下游差异，保存待复听片段。10 秒静音与从已用开发素材选定的明确非语音段各作负例，配乐中的对白另计。
5. 每组送入相同 Reazon 和 M0，核对实际中文。冻结切片上的 ASR 测试与连续输入 VAD 实验分别记账。

**完成**　有 `vad-model-comparison.json`，包含模型/适配器差异、连续性、负例和端到端语义。语音恢复且无已确认的新关键误译时，再对原9段连续PCM的全部34项做同一M0两种子评分，通用离线门槛决定E6候选池。F1 宣传数字仅作来源参考。[v4 资产来源](https://github.com/k2-fsa/sherpa-onnx/pull/2372) · [v6.2 说明](https://github.com/snakers4/silero-vad/releases/tag/v6.2) · [FireRed 特征实现](https://github.com/FireRedTeam/FireRedVAD/blob/c30ec49e8cc69642b0ee65362eba11b9d11c6e54/fireredvad/core/audio_feat.py)

## E4. Reazon 解码期热词

**输入**　原 88 个冻结切片，当前纯日语权重、2 线程和 M0。它检验解码期偏置，与已失败的普通 beam 和 MT 词表分别对照。

1. 用标题、简介或用户给定的词冻结视频级日文词表并保存来源。词表定版先于候选输出，开发参考答案只进评审资料。
2. 先核对 token 编码与 context graph 实际进入 decoder。纯日语版使用 `modified_beam_search`、`modeling_unit="cjkchar"`、`create_stream(hotwords=…)`。新 ja-en 词表另作验证。
3. 矩阵限于当前 greedy、beam4 空词表、beam4 热词 score=1.5 和 3.0。先用已知发音小样本确认热词有实际影响，再解码全 88 段。
4. 同词表在非命中视频与无关短句作负对照。统计额外插词、身份/数字/动作错误、日文变化和经同一 MT 后的覆盖。

**完成**　`hotword-comparison.json` 同时对照空词表 beam 和当前 greedy。最终相对 greedy 按通用离线门槛晋级。图未生效、只改善术语字面或整体回退则结束。[context graph 入口](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-recognizer-transducer-impl.h)

## E5. 有预算地筛新模型与小收益

### 新 ASR

按下表首筛，整个阶段最多两个新 ASR。全部先跑原 88 切片与同一 M0。切片吞吐、完整句窗口诊断和原速字幕分别计分。

| 优先级 | 精确候选与首个运行路径 | 第一项验证 |
| --- | --- | --- |
| 1 | `ibm-granite/granite-speech-5.0-470m-turboctc`，多语种 revision `1dd23f46f6d4e6eae2531982ba2e33220086dd97`；隔离环境按官方 MLX 用法 | 配置词表与权重确实含日语；完整短句和静音可稳定解码 |
| 2 | `csukuangfj/reazonspeech-k2-v2-ja-en`，revision `12b44671ff48b9aed622551d64e02fea9a2cf870`；现有 sherpa | epoch35 encoder/joiner/tokens 匹配。原 decoder 与量化组合按资产清单锁定；日语被误识成英语另计 |

每个候选首筛前锁定实际依赖版本、模型结构与文件哈希。Granite 官方要求的较新 MLX/Transformers 放隔离环境，日语缺失或适配失败时停止该运行路径。一个运行时失败最多换一个官方支持路径，成功后保留一种。

若两席中某候选因部署不可用退出，可用 Cohere 日语微调或 Fun-ASR-Nano 标准中英日 checkpoint 置换一席，全轮至多一次。以现有错误集中是否有明显删除/长段关系缺失选择一个，并先核对官方日语支持、许可证和 Mac 路径。具体 revision 在下载前冻结。最多两个候选进入完整质量首筛；含失败部署的checkpoint尝试总数至多三个。已经完成质量筛选但成绩不佳的候选占用原席位。Voxtral、MOSS、多种量化与新运行时的扩展另列后续建议。

**完成**　`asr-screen.json` 给出每个席位的加载、静音、全部切片输出、MT 覆盖和退出原因。离线门槛决定 E6 名额，公开 CER 与文件体积作为选型输入。[Granite 官方用法](https://huggingface.co/ibm-granite/granite-speech-5.0-470m-turboctc/blob/1dd23f46f6d4e6eae2531982ba2e33220086dd97/README.md) · [ja-en 资产](https://huggingface.co/csukuangfj/reazonspeech-k2-v2-ja-en/tree/12b44671ff48b9aed622551d64e02fea9a2cf870)

### 新 MT 与已有小收益

1. 若 E0 的 `m2-hit` 获得诊断例外，在 20 项独立开发单元上比较 M0 和原冻结词表。先确认确有自然命中，未命中输入复现控制。报告救回与丢失、关键错误和两种子稳定性。这只判断是否值得保留研究，正式原速名额仍按通用门槛。
2. 新 MT 仅首筛 `IndexTeam/Index-Translate-2B-GGUF` 的 `Index-Translate-2B.Q8_0.gguf`，revision `3a0eca6ce931d88d00614d427ab3ed8ff0743902`。使用支持该 Qwen3.5 架构的固定 llama.cpp Metal 构建，独立 loopback 服务，单并发。原日文 62 条与当前采样 11／29 控制逐条一致。另用34条完整来源日文做C路诊断，标为`source_provisional`，只帮助区分输入错误和MT能力，晋级用实际ASR输入。
3. 采用发布方日→简中单条模板、关闭 thinking，首轮独立句、无前文无词表。明确输出上限、context 长度、停止 token、缓存策略。原生模板与执行后端视为候选组合的一部分。词表、上下文与缓存随后各自作为单变量。
4. 先预热，核对返回的是 2B 文本模型、简中结果和实际结束原因。生成耗尽上限、输出解释或思考、混合日文与无关扩写均计失败。输出质量通过后，再与 ASR 同时运行测竞争。

**完成**　`mt-screen.json` 和逐条关键错误表齐备。至少净增 3/34 且无新增关键错误才占 E6 名额。现有贪心和 7B 结果已失败，本轮复用证据。[Index 官方模板与配置](https://huggingface.co/IndexTeam/Index-Translate-2B)

### 选择性补救的条件分支

只有多个候选显示互补且仍值得组合时，先用 E0 同尺度标签计算已有结果的理想选择上限。潜在净恢复不足 3/34 则停止。达到上限也仅触发一个离线选择器试验，总预算2小时，规则只用运行时可见的空结果、已证实的尾部未处理或预先给定信息，最多一次补救。选择规则在独立开发材料冻结；参考答案只供计分。该试验复用已测模型，ASR常驻至多两个，连同MT一起监测实际资源；最终组合仍占E6的一个席位。

v1 试验优先选择最终输出前完成的有时限补救，等待计入原速。用户已看到的错误字幕替换需要独立的修订合同及暴露时长计分。该分支成功后才规划修订协议与 Chrome 改造。

## E6. 原速组合验证

**输入**　最多两个正式过线的候选，以及每轮全新启动的默认基线。

1. 新运行时先通过实验适配器接入同一 `SubtitleBackend/SubtitleSession`。复用 [现有探针](../p0/next_whisperkit.py) 和 [replay 入口](../engine/src/subtitle_service/replay.py)。新 profile 先跑 `ready → caption → finished`、短尾、静音、取消、子进程失败和切回基线的定向检查。
2. 所有组按原 9 段、1×、200 ms 供流。随机选 A/B 或 B/A 起始次序后交错，各跑两次。保留 PCM 接纳/消费、队列最旧等待、VAD 放行、ASR/MT 起止、网关与 WS 的同一时钟关联。
3. 每轮检查语义覆盖、关键错误和短句。相同片段范围及相同日文输入用E0稳定ID沿用原派生种子，新增切片按预先冻结的文本/样本范围哈希规则派生。实验服务记录每次MT调用的种子、输入和稳定ID。种子规则改变时同轮基线一起重跑，旧20／18仅作历史参照。
4. 实跑前从离线候选池冻结最多两个配置席位，单项与组合各占一席。ASR和MT各有胜出时，优先选择离线收益较强的单项以及组合；两种单项已经占满时，组合另记后续实验。组合须已有离线同输入验证，收益不加总推测。各组只加载当前目标与固定控制组件。
5. 按本节资源口径验证整条链路。时标未人工核准时并列敏感性指标，先给 `provisional` 结论，继续可执行的生命周期与独立开发验证。

资源以 [monitor.py](../p0/monitor.py) 的 250 ms 采样为基础。冷编译、加载、预热、热态逐段和整组分别报。CPU 100% 为一个核，内存用进程树物理 footprint，Core ML等可识别的系统辅助进程单列，未采到的占用写N/A。GPU/共享内存报告整机均值、P95、峰值和同轮空闲差值；ANE 无独立计数时填 N/A。GPU共享内存与footprint可能重叠，分别列值。附已处理音频时长、空 ASR 数、MT 调用数与输出量。服务及子进程热态峰值目标为2.5 GiB，超出时记录整机压力与覆盖收益，保持实验状态，默认替换前单独裁决资源取舍。要比较等工作量的执行效率，再加同输入的单独 ASR/MT 对照。

**完成**　`realtime-comparison.json` 能从原始事件复算；所有候选以同尺度两轮结果判晋级。无候选过线时完成当前轮报告，按错误集中情况提出下一项单实验。

## E7. 真实 Chrome、盲测与长稳

**进入**　E6通过或取得待人工时标的暂定通过。先做E7a的非盲工程验收，人工参考核准后进入E7b的盲测和最终放行。两部分共用冻结的profile。

### E7a. 非盲工程验收

1. 先跑原 17 段、121 项历史回归，并列新旧参考。检查候选恢复收益和原正确保护项。
2. Chrome 做仅播放、播放加 ASR、播放加完整字幕三组资源对照，各两轮。记录 WS 与 DOM 的同一字幕 ID、可见时长和媒体时间。DOM正确覆盖要求每个必要片段连续可见至少`max(0.6秒,非标点字数/12字每秒)`。只有实际正确语义被遮挡/过早覆盖时，安排有限合并或最多两条队列的单变量显示试验。
3. 预先生成超过60分钟的单一测试文件并保存素材拼接与参考偏移清单，用单一播放器、单一WS连续1×运行60分钟。固定前中后各10分钟窗口，记录队列、延迟、热态资源；暂停、拖动、SPA换片、1.5×、全屏、接管、Worker重启、断开恢复和EOF另作生命周期测试。

**完成**　`engineering-acceptance.json` 包含原速回归、DOM、资源和长稳结果。语义尚待复听时该部分保留暂定状态，已完成的工程检查照常交付。

### E7b. 独立盲测与最终放行

参考已人工核准后，使用至少六个独立来源、60项语义和20条独立短句，覆盖对话、讲解和配乐，每个来源至多25%。`test/` 算一个来源。配置与参考在首轮候选推理前冻结。若根据盲测调参，该批材料转回归，新发布验证另取独立材料。

**完成**　历史与盲测5秒可读DOM覆盖均≥90%（历史至少109/121），句末P50≤1.5秒/P95≤3秒，短句首条正确P90≤4.5秒，静音零字幕、无新增关键误译。队列积压连续10秒超过2秒判失败；末个热态窗口 footprint 中位数增长超过 `max(10%,128 MiB)` 时定位并复测。交付 `acceptance.json` 与剩余失败清单，默认替换和发布按单独授权执行。

## 3. 两份反馈的采用与修正

| 建议 | 评估和本文安排 |
| --- | --- |
| FireRed 必能滤 BGM，97.57% 直接代表流式效果 | 该指标属于非流式 VAD；binary voice 还包含歌声。E3 单测 Stream-VAD 的连续性、音乐误收和对白恢复 |
| Parakeet 零幻觉，假名能保证 MT 还原 | 已测纯静音有输出，固定日文到中文也有错误。原配置保留失败证据，新版本须有独立假设再入场 |
| GPU 争抢是当前默认的主要瓶颈 | 当前 Reazon 在 CPU，既有链路无持续积压。GPU 组合按 E6 实测，前端完整性和语义优先 |
| 当前以固定2秒硬切，换流式API就有持续缓存 | 当前端点由Silero决定。网络包、模型窗口和语义段分别计量；新运行时须从实际encoder缓存与重复计算日志验证增量能力 |
| 换系统音频捕获并显示日语快轨 | 产品入口为 Chrome 标签页音频与最终简中；采音或协议变更由后续实测暴露的缺口触发 |
| 正则句末保证语义，20行能消除70%错乱 | 句尾形式和识别前缀不足以保证否定完整。现有切分预筛已回退，先由 E1/E3 定位边界 |
| Prefix KV cache 带来零成本上下文 | 缓存只复用实际相同前缀；滑动上下文、输出与占用仍须计量。上下文方案已有回归，首筛独立句 |
| 旧 VAD 与 200 ms 调用粒度 | 官方资产匹配本机 v4，源码存在调用边界效应。E1/E3 验证收益，源代码机制与漏句根因分开判断 |
| WhisperKit no-speech gate 导致空段 | 当前版本概率常量为0，默认 gate 不触发。E2 优先检查1秒窗口和实际解码路径 |
| Granite、ja-en、Index 值得新增 | 有明确新 checkpoint 或模型路线，进入有限席位首筛，公开成绩不作本机门槛 |
| Sakura 1.5B 可作为另一 MT | 发布方有该模型，但其目标域与非商用条款需逐项核对。当前新 MT 席位先给 Index；Sakura 留作目标域素材补齐后的替代建议 |
| openasr、TypeWhisper、MOSS 等整体替换 | 作为模型执行/生命周期参考；只有具体候选过线后才复用对应组件 |
| 理想选择上限与 m2-hit 小收益 | 分别按 E5 的条件分支和独立开发诊断执行，正式门槛保持单一来源 |

FireRed 指标、Index 模板、Sakura 模型身份均已核对第一方资料。其运行速度、CPU预算和本机整机内存仍待实验。[FireRed 模型说明](https://huggingface.co/FireRedTeam/FireRedVAD) · [Index 模型说明](https://huggingface.co/IndexTeam/Index-Translate-2B) · [Sakura 发布列表](https://huggingface.co/SakuraLLM)
