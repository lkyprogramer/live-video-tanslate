# P0 本机实时日译中 A/B

## 结果与决策

两组都跑通了 16 kHz 音频 → WhisperLiveKit `/asr` → Hy-MT2 简中输出，**均未达到观影验收门槛**。每组尝试相同的 17 段、29 分 45 秒音频，按 1× 原速串行回放。中断记录和未覆盖的后续句子都纳入结果。

| 指标 | `small` | `large-v3-turbo` |
| --- | ---: | ---: |
| 首条中文 P50 / P95，从每段播放起点算 | 4.38 / 15.71 秒 | 5.43 / 18.07 秒 |
| 句末到可用中文 P50 / P95，按 15 秒内有效配对 | 0.73 / **3.59 秒**（51 句） | 3.02 / **7.07 秒**（24 句） |
| 15 秒内漏译或无可用译文 | **57.9%**（70/121） | **80.2%**（97/121） |
| 5 秒内得到可用译文，目标 ≥ 90% | **40.5%**（49/121） | **14.9%**（18/121） |
| 因 ASR 积压中断 | **2/17** | **11/17** |
| 本地缓存就绪后启动到 `/health` ready | 8.81 秒 | 13.52 秒 |

首条中文统计 16 段有声输入，包含片头静音和语气词，无法单独说明字幕质量。短句对照从标注语音起点算，首条合格中文分别如下。两组的 10 秒静音对照都未生成字幕。

| 1–3 秒短句 | `small` | `large-v3-turbo` |
| --- | ---: | ---: |
| 我这边有照片 | 2.85 秒 | 5.30 秒 |
| 有很多人我不认识 | 4.62 秒 | 未命中 |
| 位于西欧 | 未命中 | 未命中 |
| 切换幻灯片 | 未命中 | 未命中 |

按中断时钟估计，`small` 有 108 个参考单元已到句末，`large-v3-turbo` 有 42 个。只比较两组都到达句末的同一批 **42 个单元**，`small` 在 15 秒内有 15 个可用，`large-v3-turbo` 有 24 个可用。只比较两组都配上的 **15 个单元**，P95 分别为 **5.95 秒和 7.12 秒**。`large-v3-turbo` 在共同播放到的部分保留了更多语义，但积压更早中断，整段观看时覆盖更低。样本包含 106 个同一会议来源的单元，本轮结果适用于当前配置和样本集。

**定位。** 讲解视频分别在播放第 47.01 秒和 20.41 秒触发 `Transcription backlog did not clear within 1 seconds`。第一次会议中断前，WS 报告的 ASR 积压 P95 分别为 14.6 秒和 15.8 秒。两组发送调度最大迟到均小于 0.10 秒，WS 没有报告翻译推理错误。将正确日文直接交给同一个 Hy-MT2，约 0.30 秒译出了“运动宪章”。送入实时 ASR 实际产生的“運動検証”则译成了“运动验证”。独立翻译也把副语言术语译成了“平行语言信息”，因此吞吐和术语质量需分别验收。逐段数据（本地 `p0/evidence/comparison.json`） · 译文对照（本地 `p0/evidence/mt-control.json`）

**下一步决策。** 先把 ASR 达标作为插件开工条件。用本轮中断的带配乐讲解和双人对话做短回归，保留同一 Hy-MT2，优先试 WhisperLiveKit 的 `mlx-whisper` + LocalAgreement，验证全 MLX 识别路径能否在本机持续跟上，再用同一套 P0 复跑。通过后，扩展仍可沿用标签页音频和 `/asr` 接口，字幕适配应以本轮滚动快照为测试样本。历史裁剪会改变 `start`，只按行起点去重会反复显示旧译文。[LocalAgreement 的 MLX 实现](https://github.com/QuentinFuxa/WhisperLiveKit/blob/13ee8515f136e0fd0bf31fb8ab0b63ab10670fa2/whisperlivekit/local_agreement/backends.py)

## 环境与样本

2026-11-06，Apple M1 Pro、32 GiB、macOS 26.7.2，ARM64 Python 3.12.12。WhisperLiveKit `13ee8515f136e0fd0bf31fb8ab0b63ab10670fa2`，包版本 `0.2.26`。两组使用同一 `SimulStreaming`、VAD、Hy-MT2 1.8B 4-bit 和队列限制。固定版本的 `mlx-whisper` 路径使用 MLX 编码器与 PyTorch CPU 解码器。启动参数、依赖版本和实际运行配置保存在 `p0/evidence/`。[WhisperLiveKit ASR 实现](https://github.com/QuentinFuxa/WhisperLiveKit/blob/13ee8515f136e0fd0bf31fb8ab0b63ab10670fa2/whisperlivekit/simul_whisper/backend.py)

## 计分

- **首条中文**记录每段从开始播放到 WS 返回首个含汉字且无日文假名的新增译文。它是原始到达时间，可能包含片头静音或无效译文。人工审查另外记录首个可用译文，以及四条 1–3 秒短句从语音起点到可用译文的时间。
- **句末到中文**用审查者确认的首次可用中文快照的单调时钟到达时间减去参考结束点。会议使用独立发布字幕的时间码，手动合并明显拆行的语义单元。CSJ 使用人工转记时码。会议字幕时码与实际语音边界可能有误差。提前出现按 0 计入分位数，原始负值保留供核对。
- **漏译与迟到**共用同一分母。106 个会议语义单元和 15 个 CSJ 单元纳入句末评分。只接受核心含义正确的字幕。错译、没有译文、译文迟于 15 秒观察窗计入未命中。5 秒不可用率再包含 5–15 秒才到达的可用译文。P95 用 15 秒内有效配对计算，并列报告未命中，避免丢句拉低延迟指标。四个重复抽取的短句只用于首条对照。
- **快照**按源顺序比较前后中文，识别历史裁剪和真正新增内容，跳过静音行和重复状态。试跑中裁剪会移动同一行的 `start`，单靠行起点会把原有译文误认为新字幕。同一快照中的多条中文可以对应多个参考单元。逐条审查用事件 ID 回指原始 WS 记录。

## 复现

在项目根目录运行。当前 Mac 的虚拟环境与模型缓存已可复用。依赖版本见 `p0/evidence/python-freeze.txt`。模型仓库与 revision 在 `p0/run.py` 中锁定。缓存包括 MLX encoder、Hy-MT2 和官方 PyTorch `.pt`。Hugging Face Hub 2.4 的离线启动需要完整 snapshot，包括 README 等元数据。`p0/evidence/source-sha256.txt` 用于校验原始素材。[官方 PyTorch 权重路径和校验值](https://github.com/openai/whisper/blob/main/whisper/__init__.py)

```sh
.venv/bin/python p0/prepare.py
/usr/bin/caffeinate -i .venv/bin/python -u p0/run.py small p0/evidence/repeat-small
/usr/bin/caffeinate -i .venv/bin/python -u p0/run.py large-v3-turbo p0/evidence/repeat-turbo
```

引擎每组启动一次并完成预热，服务只绑定 `127.0.0.1`，回放用 WS Bearer 令牌，测试结束停止进程。`p0/review.py` 可列出翻译变更、辅助语义复核和根据判定文件重算指标。当前 P0 以 WS 返回为终点，Chrome 采音、传输调度和渲染的额外开销由后续阶段验证。

两次正式回放都记录了全部 17 段结果。运行器因为存在积压中断而返回 1。`p0/evidence/small/` 和 `p0/evidence/large-v3-turbo/` 保存原始 WS、每段 EOF 状态和引擎日志。下列命令用本轮逐句判定重算两个模型的结果。

```sh
.venv/bin/python p0/review.py p0/evidence/small --verdict p0/evidence/small-verdict.json
.venv/bin/python p0/review.py p0/evidence/large-v3-turbo --verdict p0/evidence/turbo-verdict.json
```
