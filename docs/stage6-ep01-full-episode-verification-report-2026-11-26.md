#### 关键复现实验：`M560` 丢字根因隔离（实测对比）

抽取开篇及剧中的 3 个典型丢字切片，在同一输入音频下横向对比 `ane_greedy`、`gpu_greedy` 与 `gpu_beam`：

**实测证明两重根因**：
1. **`ane_greedy` 与 `gpu_greedy` 100% 数值等价**，ANE 量化与 CoreML 推理本身不是丢字原因；
2. **`greedy` 解码在 `4s+` 多人对话窗下会发生整段前句塌缩**（`seg2_full` 上 `gpu_beam` 完整保住了两位说话人的全部台词，而 `greedy` 彻底丢掉前半句——这解释了为什么 D0 单人讲座中 `greedy` 看起来和 `beam` 差不多，但一上真实日剧立刻翻车）；同时当同一切片内存在**一远一近、音量悬殊的两个人**时（如 `seg575`），`vad_pause_ms=350` 将两人拼在一起导致全局 Mel 均值方差归一化压制弱声说话人，连 `gpu_beam` 也只输出后半声大的 `"はい。"`。

### 5.2 基于真因的数据驱动下一轮工程优先级（不再盲目微调）

从本轮全集归因看，**进一步挤压 ANE 编码器十几毫秒已毫无边际意义**，下一轮应严格按实测痛点比例依次攻关：

1. **P0（解决 `67.5%` 的 `E1` 丢字 + `20.8%` `E6` Draft 反转）—— 修复 `greedy` 丢字与多说话人过长切片**：
   - **重评估混合解码（Hybrid Decoding）**：仅 Draft 使用超快 `greedy`（`28.8ms`），**Final 恢复 `beam` 解码（或实现仅做声学前向复用编码器输出时对疑似丢字/长切片回落 beam）**——本轮在 `seg2_full` 已直接验证 `beam` 可立即救回 `greedy` 吞掉的整句；
   - **缩短 VAD 拼接跨度与保护说话人边界**：将 `vad_pause_ms` 从 `350ms` 下探评测（如 `180–240ms`）并将 `max_segment_s` 从 `4.5s` 评估收紧至 `2.8–3.2s`，减少响度悬殊的两位说话人被拉进同一全局 Mel 归一化窗而互吞。
   - **防止劣质 Final 反向覆盖优质 Draft**：对最终切片的字数/音频时长比设定保护（或把更长窗中识别密度崩塌的切片重新切分/回落 `beam`）。
2. **P1（解决 `47%` Draft 跳变与 `3.11s` 首字等待）—— 重构 Draft 门控与显示策略**：
   - 日语 SOV 语序下，未出现核心谓语前的残句不应硬送 MT（否则 47% 被完全推翻反而干扰阅读）；或 UI 明确以增量追加/稳定句边界切分代替半句硬猜。
   - 对纯标点（`。/！/？`）ASR 结果在送入 MT 前直接拦截，避免浪费 `250ms` GPU 算力与产生 `22` 条无意义 `translation_invalid` 告警。
3. **P2（解决 `18.1%` `E3` MT 错译与 `3.6%` `E4` 上下文遗忘）—— 强化口语与长上下文翻译质量**：
   - 在 `Qwen3Translator` 放宽或重构滚动 KV Cache（取消每 `2` 句/`5s` 粗暴硬清空，改为保留最近 `4–6` 轮的滑动对话摘要与剧集常见专名/称谓约束）；
   - 通过全集 Arm B 基准（仅用 654 句权威日文 `30s` 脚本，~3 分钟即可回归验证）迭代提示词与模型对比，修复诸如 `30分の1 -> 三分之一`、`ポケベル -> 宝可梦/手机`、`何名様 -> 您是哪位`、`湯飲み -> 汤瓶`、`おかえりなさい/いってらっしゃい` 情景误译等问题后再并入主链路。
